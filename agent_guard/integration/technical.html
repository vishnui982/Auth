THE SECURITY MODEL

Authorization is evidence about one exact action.

Agent Guard does not decide whether a goal sounds reasonable. It authorizes a concrete action: a principal, operation, resource, and parameters. A protected resource executes only after it verifies the authorization against the request it actually received.

01
Normalize the tool request.An email, HTTP request, or MCP tool call becomes one canonical V2 Action. Destination, method, body, tool name, and actor are included.
02
Reach three-way agreement.OPA/Rego, the compiled Lean evaluator, and the Python reference checker evaluate the same state transition. Missing output or disagreement fails closed.
03
Issue signed authorization evidence.An allow certificate binds the action hash, policy hash, state hash, nonce, actor, evaluator manifest, and expiry. Permission to attempt is not proof of an effect.
04
Verify at the receiving tool.The protected resource reconstructs an Action from the authenticated, actual request. Any substituted body, path, destination, actor, or stale state causes rejection.
05
Commit effect and evidence together.For the controlled local mocks, nonce consumption, the mock effect, and its signed observation are written atomically. The delivery journal distinguishes authorized, dispatching, confirmed, rejected, and unknown.

POLICY INVARIANTS

DEFAULT_DENY

A missing rooted authority witness is a denial. The agent cannot create authority by claiming intent.

EXACT_ACTION_BINDING

Changing a recipient, request body, HTTP path, method, tool argument, or actor changes the action commitment.

INFORMATION_FLOW

Reading payroll activates PAYROLL_PRIVATE; derived data inherits it, and a destination must explicitly accept it.

ONE_TIME_EVIDENCE

The signed nonce is consumed by the protected resource. Replaying the same certificate cannot create another effect.

DELEGATION_SCOPE

Delegation is attenuated. It carries only the parent grant’s allowed operation, resource scope, expiry, and remaining delegation depth.

CASCADE_REVOCATION

Revoking a parent grant invalidates every descendant authority chain that depends on it.

WHAT THE CHAIN MEANS

canonical Action ↓ hash OPA + Lean + reference decision ↓ signed authorization certificate protected resource verifies actual request ↓ atomic mock effect + signed observation append-only event / delivery trace

BOUNDARY OF THIS DEMO

Confirmed means the supplied local mock service recorded an effect and signed an observation. It does not claim SMTP delivery, an external payment, production network security, or arbitrary remote idempotency. The protocol core is unchanged by this product-demo layer.
